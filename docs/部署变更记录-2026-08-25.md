## 二、部署架构要点

- 部署基于仓库 `deploy/` 目录：`docker-compose.yml` + `.env` + `docker-compose.override.yml`
- 前端经 nginx（8080）反代：`/api/` → webapi:5001、`/auth/` → auth:5000（剥 `/auth` 前缀）、`/hub/`、`/assistantHub` → webapi WebSocket

## 四、线上问题排查与修复过程（按时间线）

1. **登录 500 — `Table 'd0001.TSS_RESOURCE' doesn't exist`**
   - 现象：数据库已导入但登录报错。
   - 根因①：导入的表为小写 `tss_resource`，代码查询大写 `TSS_RESOURCE`，MySQL 容器 `lower_case_table_names=0`（Linux 默认，大小写敏感）。系统按 Windows 环境（不区分大小写）开发。
   - 根因②（后续）：登录接口要求表单值先 JSON 序列化（前端 axios `tran` 转换），直接发裸文本会 500——curl 测试方式问题，非系统 bug。
   - 修复：`--lower_case_table_names=1`；因该参数初始化后不可改，备份全库（`/opt/realso/d0001-backup-20260825.sql`，450MB/92 表）→ 重建数据卷 → 自动回导。

2. **登录成功但业务接口 401**
   - 根因：Auth 在容器内以 `http://localhost:5000` 请求 IdentityServer 签发 token（`iss=http://localhost:5000`），而 webapi 校验 Authority 为 `http://auth:5000`，discovery 文档 issuer 与 token iss 不一致。
   - 尝试过的方案：设 `IssuerUri=http://auth:5000`——失败，IdentityModel 客户端要求 authority 与 discovery issuer 完全一致且非 loopback 强制 HTTPS。
   - 最终修复：保持签发链路不变，webapi 侧显式 `ValidIssuer=http://localhost:5000`（compose 可配 `Auth__Issuer`）。

3. **Word 模版编辑器 404 / OnlyOffice API 加载失败**
   - 根因：前端构建时写死 `localhost:8088`，浏览器从访问者本机加载 OnlyOffice API。
   - 修复：前端动态取「浏览器主机 + :8088」；OnlyOffice 容器接入 realso 网络；appsettings 两处 URL 改为容器名。
   - 注意：数据库中 2022–2024 年的历史文件记录在服务器上无物理文件，打开报"文件不存在于磁盘"属正常；只有新上传的文件可在线编辑。

4. **编辑器报"文档安全令牌的格式不正确"**
   - 根因：OnlyOffice 服务器 JWT 校验三层全开，后端无 token 生成逻辑。
   - 修复：关闭 DS 的 JWT（browser/inbox/outbox）。如需恢复，需后端用 DS secret `<DS-secret>` 对编辑器配置签名。

5. **编辑器报"下载失败"**
   - 根因：OnlyOffice 内置 SSRF 防护拒绝下载私有 IP（`webapi` 解析为 172.19.0.4）。
   - 修复：`request-filtering-agent.allowPrivateIPAddress=true`，并用 DS 转换服务实测通过（FileResult 返回成功）。

6. **GROUP BY 报错（`only_full_group_by`）**
   - 根因：MySQL 8.0 默认严格模式，系统 SQL 为旧版风格。
   - 修复：全局及 compose 启动参数移除 `ONLY_FULL_GROUP_BY`。

7. **切换外网代理访问（101.42.97.106）**
   - 本服务器无公网/不能访问外网，由代理服务器（同 VPC，内网 172.21.0.8）反代。
   - 对外端口：6080（后台）/6088（OnlyOffice）/6001（API）/6000（认证）；本机端口映射不变。
   - 前端 OnlyOffice 端口改为动态「浏览器端口+8」；插件 webapi 端口改 6001；`OnlyOffice:ApiUrl` 改公网地址。
   - 关键验证：本机经 VPC 内路由可直连代理公网 IP（3.5ms），因此公网地址对 docservice 同样可达。

8. **编辑器缓存文件 URL 错误（`ERR_NAME_NOT_RESOLVED: hs2_backend_onlyoffice`）**
   - 根因：代理服务器的 nginx 未正确设置 `proxy_set_header Host`（nginx 默认传 upstream 名），DS 的 `$the_host` map 优先取 `X-Forwarded-Host`，导致 docservice 生成的缓存文件 URL 主机名变成 upstream 名。
   - 排查要点：docservice 生成的 URL 反映它收到的头；曾误改 `/etc/onlyoffice/documentserver/nginx/includes/`（模板树），实际生效的是 `/etc/nginx/includes/`。
   - 修复：在 DS 容器内 `/etc/nginx/includes/http-common.conf` 固定 `Host` 头与 `$the_host` map 为公网地址，一劳永逸（代理侧配置问题依旧存在但不再影响）。

9. **外网模式编辑器"下载失败"（document.url 内网域名）**
   - 根因：编辑器配置的 `document.url` 为 docker 内网域名 `webapi:5001`，DS 9.4 前端在浏览器侧校验该 URL，用户浏览器无法解析 → 失败（docservice 日志无新记录即为浏览器侧失败的特征）。
   - 修复：`OnlyOffice:ApiUrl` 改为公网 `http://101.42.97.106:6001`，浏览器与 docservice 双侧实测 200。

10. **"文档安全令牌的格式不正确"复现（第二次）**
    - 根因：DS 容器 `local.json` 的 JWT 三开关被某操作还原为开启（容器未重建，其余修复均在）。
    - 修复：再次关闭并重启 DS 服务；提醒若第三次出现需排查重置源头。

11. **文件预览"下载失败"**
    - 根因：`rs-onlyoffice-preview/index.vue` 用旧逻辑 `replace('localhost','host.docker.internal')` 拼下载地址，API 地址改相对路径后拼出相对 URL，DS 无法下载。
    - 修复：改为动态绝对地址（浏览器主机 + 6001 + `/api/file/{id}`）；`/api/file/{id}` 无鉴权（密码保护证书除外），两侧实测 200。

13. **JWT 反复重置（第三次，"文档安全令牌"随 docker 重启复现）**
    - 根因：DS 容器入口脚本每次启动按 `JWT_ENABLED`（默认 true）重写 local.json。
    - 根治：`-e JWT_ENABLED=false` 重建容器；重启验证通过。

14. **登录成功但业务接口 401（`signature is invalid`）**
    - 根因①：Auth 每次启动随机生成 RSA 签名密钥，重启即导致所有已签发 token 失效、webapi 缓存的公钥不匹配。
    - 根因②：上游新登录代码不再传 PASSWORD 参数，而 DB 的 F02 模板仍含 `@PASSWORD` → `Parameter '@PASSWORD' must be defined`。
    - 根因③：新代码把明文密码升级为 89 字符哈希，超出 `PASSWORD` varchar(64) → `Data too long`。
    - 修复：持久化签名密钥（`/opt/realso/auth-signing-key.json` 挂载 + `ImportParameters` 加载）；DB 模板去 PASSWORD 条件；字段扩至 varchar(200)。重启 auth 后旧 token 仍有效（实测通过）。

12. **前端 vendor.js 下载慢（3MB/25s）**
    - 排查：内网直连与代理内网转发均 0.14s，慢在公网路径；本机公网出口 1M、代理 5M、办公室网络正常。
    - 已做优化：gzip 级别 1→6（3.1MB→2.64MB）、禁止 source map（-29MB）。
    - 结论：用户侧实测仍慢时，优先检查代理服务器实时带宽占用与端到端链路（手机热点对比测试可定位）。

## 五、构建环境（本机留存）

| 项 | 位置/值 |
|----|---------|
| .NET SDK 2.2.402 | `/opt/dotnet`（使用需 `PATH=/opt/dotnet:$PATH DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1`） |
| OpenSSL 1.1 兼容库 | `dnf install compat-openssl11`（SDK 2.2 不支持 OpenSSL 3） |
| .NET 2.2.8 运行时（镜像内） | `netcore/runtime/dotnet` |
| publish 产物 | `netcore/publish/{webapi,auth}` |
| 前端构建 | `p-admin/dist`（Node 22 需 `NODE_OPTIONS=--openssl-legacy-provider`，npm 源 npmmirror） |

**重新构建命令**（在服务器上）：

```bash
# 后端
cd /opt/realso/hs2.0/netcore
export PATH=/opt/dotnet:$PATH DOTNET_ROOT=/opt/dotnet DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1
dotnet publish <项目绝对路径> -c Release -r linux-x64 -o ./publish/<webapi|auth> --self-contained false
docker build --platform linux/amd64 -f Dockerfile.local --build-arg APP=<webapi|auth> -t realso-<webapi|auth>:latest .

# 前端
cd /opt/realso/hs2.0/p-admin
NODE_OPTIONS=--openssl-legacy-provider npm run build
cd /opt/realso/hs2.0
docker build --platform linux/amd64 -f deploy/Dockerfile.p-admin -t realso-admin:latest .

# 部署
cd /opt/realso/hs2.0/deploy
docker compose -p realso up -d
```

> 注意：`dotnet publish` 的 `-o` 相对路径会解析到项目目录下，构建前需把产物移到 `netcore/publish/`（Dockerfile 构建上下文要求）。

## 十、常见错误速查表

| 现象 | 快速定位 | 处理 |
|------|---------|------|
| 登录 500 `Table 'TSS_RESOURCE' doesn't exist` | 大小写敏感 | 查 mysql 容器 `lower_case_table_names` 是否为 1（compose 已固定） |
| 登录 500 `Parameter '@PASSWORD' must be defined` | DB 的 F02 模板与新代码不匹配 | `UPDATE tss_resfilter SET FILTERSQL='A.USERNAME=@USERNAME AND A.ISUSE = 1' WHERE FILTERCODE='F02' AND RESOURCEID=(SELECT ID FROM tss_resource WHERE RESOURCENAME='VSS_USER')` |
| 登录 500 `Data too long for column 'PASSWORD'` | 字段宽度不足 | `ALTER TABLE tss_user MODIFY PASSWORD VARCHAR(200)` |
| 业务接口 401 `signature is invalid` | 签名密钥 | ① 重启 webapi（清公钥缓存）；② 确认 auth 日志有「签名密钥已从 /app/signing-key.json 加载」；③ 密钥文件 `/opt/realso/auth-signing-key.json` 存在且挂载 |
| 业务接口 401（其他） | token/issuer | 确认 compose webapi 有 `Auth__Issuer=http://localhost:5000`；登录后 token 的 iss 应为 localhost:5000 |
| 编辑器「文档安全令牌的格式不正确」 | DS JWT | 容器已用 `JWT_ENABLED=false` 重建（根治）；若复现查 `docker inspect onlyoffice-document-server --format '{{.Config.Env}}'` 是否含 JWT_ENABLED=false |
| 编辑器「下载失败」 | 下载地址 | ① `OnlyOffice:ApiUrl` 应为 `http://101.42.97.106:6001`；② DS `request-filtering-agent.allowPrivateIPAddress=true`；③ 两侧 curl 该 URL 都应 200 |
| 浏览器 `ERR_NAME_NOT_RESOLVED: hs2_backend_onlyoffice` | DS 缓存 URL Host 错误 | DS 容器 `/etc/nginx/includes/http-common.conf` 应有固定的 `101.42.97.106:6088`（Host 头 + $the_host map） |
| GROUP BY 报错 | sql_mode | compose 已固定去除 ONLY_FULL_GROUP_BY；临时：`SET GLOBAL sql_mode='STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION'` |
| 前端 401/请求到本机 | urls.js 被还原 | 检查 6 项关键修复清单（见九.1） |
| OnlyOffice 容器被重建 | 容器内修复丢失 | 重放：JWT_ENABLED=false（重建参数）+ 私有 IP 放行 + nginx http-common.conf 固定 Host + fieldinserter 插件 + `docker network connect realso_default` |

### 运维注意（新增）

1. **auth/webapi 容器重建后必须重启 admin**：nginx 只在启动时解析 upstream 主机名，后端容器重建换 IP 后若不动 admin 会出现 **502**。现象：auth/webapi 直连正常、经 8080 502 → `docker compose -p realso restart admin`
2. **OnlyOffice 数据目录是软链**：`/app/onlyoffice/DocumentServer -> /data/onlyoffice`。容器重建（docker rm/run）后软链仍在宿主机，挂载路径不变即可
3. 旧 docker 卷 `realso_mysql_data`、`realso_upload_data`、`realso_log_data` 仍保留在磁盘上（数据已迁出），确认稳定后可 `docker volume rm` 清理
